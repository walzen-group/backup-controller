3.2 The gap: the spec's CEL rules make the CRD invalid at install
The worker measured this, and meta-w2 read the measurement from its transcript rather than
re-running it. Without a bound on the MoverPodLabels map:

  start envtest control plane: unable to install CRDs onto control plane: unable to create CRD
  instances: unable to create CRD "volumerestores.backup.wlz.li": CustomResourceDefinition.apiextensions.k8s.io
  "volumerestores.backup.wlz.li" is invalid:
  spec.validation.openAPIV3Schema.properties[spec].properties[moverPodLabels].x-kubernetes-validations[1].rule:
  Forbidden: estimated rule cost exceeds budget by factor of more than 100x (try simplifying the rule,
  or adding maxItems, maxProperties, and maxLength where arrays, maps, and strings are declared)

With +kubebuilder:validation:MaxProperties=16 added to the field, the same install still fails:

  spec.validation.openAPIV3Schema.properties[spec].properties[moverPodLabels].x-kubernetes-validations[1].rule:
  Forbidden: estimated rule cost exceeds budget by factor of 6.0x

So the two label rules the task-2 spec mandates cannot be installed on an unbounded map, and the
envtest suite cannot start until a bound controller-gen can emit is in place. The API server's own
message names the remedy (maxItems, maxProperties, maxLength). docs/api.md's validation table and
the task-2 spec's marker table state no bound for moverPodLabels.
