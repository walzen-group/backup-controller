## Differences and consequences

### h. No library health route

The design asks whether task 5 can add a liveness or readiness probe beside metrics. The library creates an HTTP server only when both endpoint and metrics path are non-empty, and that server registers the configured metrics path. It does not register `/healthz`, `/readyz`, or another health path. Source: `/home/nixos/go/pkg/mod/github.com/kubernetes-csi/lib-volume-populator/v3@v3.3.0/populator-machinery/metrics.go:96-122`.

[INFERENCE] Task 2 is unaffected. [INFERENCE] Task 3 needs no health handler. [INFERENCE] Task 4 must not claim that the library supplies a health endpoint. [INFERENCE] Task 5 cannot point a probe at a library health path; the Deployment needs a separate health handler or a probe design that uses an endpoint the binary actually exposes. Source basis: `/home/nixos/go/pkg/mod/github.com/kubernetes-csi/lib-volume-populator/v3@v3.3.0/populator-machinery/metrics.go:96-122`.

### i. No image in provider-function mode

The design says task 4 should require an image flag even when the controller uses provider callbacks. In v3.3.0, `ImageName` belongs only to `PodConfig`. `RunControllerWithConfig` rejects simultaneous PodConfig and ProviderFunctionConfig, and the provider branch invokes callbacks without creating a pod or reading an image. Sources: `/home/nixos/go/pkg/mod/github.com/kubernetes-csi/lib-volume-populator/v3@v3.3.0/populator-machinery/controller.go:175-193,296-298,800-833`.

[INFERENCE] Task 2 is unaffected. [INFERENCE] Task 3 should construct `ProviderFunctionConfig` with the three callbacks and should not invent an image dependency. [INFERENCE] Task 4 should treat `--image` as unnecessary for this provider-function binary, unless the binary keeps the flag for an external packaging contract. Passing an image to the library cannot configure provider mode. [INFERENCE] Task 5 should not require an image value to make the provider callbacks work. Source basis: `/home/nixos/go/pkg/mod/github.com/kubernetes-csi/lib-volume-populator/v3@v3.3.0/populator-machinery/controller.go:175-193,296-298,800-833`.
